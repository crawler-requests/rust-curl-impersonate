2. record
   tools/gen_fingerprints.py now carries an `http3` block for chrome160 with
   exactly those values (transport_parameters, settings, pseudo_order masp).
   `python3 -I tools/gen_fingerprints.py` writes 195 records; chrome160 has
   both `tls`/`http2` (from tls.peet.ws) and `http3` (from NetLog).

3. live echo (built from this tree)
   command: target/release/examples/h3probe chrome160 quic.nginx.org /
   result:  `:status: 200`, `x-quic: h3`, body 2523 bytes
   h3probe now resolves records through `Profile::find` + `Client::http3_endpoint`,
   so a library record with an `http3` block is a first-class H3 target.

4. quinn's active_connection_id_limit agrees
   quinn advertises 5 and Chrome 160 sends 5, so the two match with no
   override. The Firefox (8) / Safari (64) presets are the ones that need the
   queue resized; see h3-active-connection-id-limit.txt.

5. fix: library HTTP/3 profiles were losing the record's TLS handshake
   Before this change `Fingerprint::http3_profile()` built every field from
   the `http3` block alone and defaulted the rest: key_shares was hard-coded
   to `&[]` (so BoringSSL sent no key share at all), and curves, grease,
   alps, ech_grease, session_ticket, permute_extensions, extension order,
   cert compression, delegated credentials and record_size_limit all fell to
   "unset" instead of the record's TLS values. chrome160's profile was
   therefore a QUIC ClientHello with no GREASE, no ALPS, no key share.
   Now every knob falls back to `self.tls` (the same rule curl-impersonate
   uses for http3_curves / http3_sig_hash_algs / http3_tls_extension_order),
   and `Http3Fingerprint::key_shares` exists to override it per record.
   After the fix chrome160's QUIC inputs are byte-identical in shape to the
   chrome152 preset: curves X25519MLKEM768/X25519/P-256/P-384, 2 key
   shares, GREASE on, ALPS on, 17 captured extensions.
   Regression test: tests/fingerprints.rs
   library_http3_profile_inherits_the_records_tls_handshake.

6. note on the earlier probe attempts
   260 (H3_REQUEST_REJECTED) replies from quic.nginx.org are the nginx edge's
   per-source-IP application policy; identical requests succeed seconds later
   and the QUIC/TLS/H3 handshake completes every time.
