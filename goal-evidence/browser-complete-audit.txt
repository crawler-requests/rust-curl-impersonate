  Chrome compares as a set because Chromium permutes the extension list on
  every connection; comparing order would report false mismatches
  (chrome114 sends 16 extensions, same ids, different order).

what the remaining 6 are, and why they are the old ones
  utls_ios11/12      NPN (13172). Deprecated; BoringSSL removed it.
  utls_360_7_5       RC4 suites, DSA sigalgs, NPN, ChannelID 30031, and it
                     omits extended_master_secret which BoringSSL always sends.
  tlsclient_cloudflare  RC4-era TLS 1.2: TLS_EMPTY_RENEGOTIATION_INFO,
                     rsae_pss_pss_* sigalgs, encrypt_then_mac.
  android_nike       the capture greases only the key share; BoringSSL's
                     GREASE switch covers every list, so one extra GREASE
                     cipher appears. JA4 is identical either way.
  android_confirmed2 fixed earlier this session (empty padding extension).

  RC4, DSA and NPN were removed from BoringSSL for security. Reinstating
  them means carrying broken crypto, which is a deliberate "no" rather
  than an unimplemented feature. Every one of them is a >=2013 client.

five and ten year windows
    2021+  chrome >=103, firefox >=102, safari >=15, edge >=106
           every one matches except the utls_ NPN pair, which are uTLS
           definitions of iOS 11/12 (2017/2018 clients)

    2015+  all of the above plus Chrome 58 (2017) onward, Firefox 55
           (2017) onward.
