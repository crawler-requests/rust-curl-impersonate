HTTP/3: active_connection_id_limit fix — live verification
date: 2026-11-17

problem
  Firefox (8) and Safari (64) H3 presets advertise
  active_connection_id_limit while quinn-proto always sent CidQueue::LEN (5)
  and sized its remote-CID window to that constant. The server filled the
  window it was told we accept, quinn hit its own smaller ring and aborted:
      TransportError CONNECTION_ID_LIMIT_ERROR (0x9)
  Instrumented capture showed the offending NEW_CONNECTION_ID:
      seq=5 retire_prior_to=0 active_seq=0 -> insert() over the 5-slot ring.
  chrome145-152 presets were unaffected because their parameter string uses
  the `chosen@alternative` form (`17:1@1,GREASE`), which the encoder could not
  parse, so the token was dropped and quinn's default value was sent.

changes
  vendor/quinn-proto/src/cid_queue.rs
    CidQueue buffer is a Vec sized by with_limit(cid, limit); all ring
    arithmetic uses buffer.len(). CidQueue::new keeps the 5-slot default.
  vendor/quinn-proto/src/config/transport.rs
    TransportConfig::active_connection_id_limit (default CidQueue::LEN);
    Debug impl updated.
  vendor/quinn-proto/src/connection/mod.rs
    rem_cids = CidQueue::with_limit(rem_cid, config.active_connection_id_limit).
  vendor/quinn-proto/src/transport_parameters.rs
    advertised active_connection_id_limit = config.active_connection_id_limit.
  src/quic/params.rs
    EncodedParams::active_connection_id_limit records parameter 0x0e;
    parse_u64 accepts curl-impersonate's `chosen@alternative,...` form so
    `17:1@1,GREASE` and `17:1@GREASE,1` both send their chosen value.
    New test: active_connection_id_limit_keeps_the_chosen_value.
  src/quic/endpoint.rs
    transport_config() copies the preset limit into TransportConfig.

tests
  cargo test --workspace: lib 31, api 10, fingerprints 19, providers 15,
  wire 13, doc 2 - all pass.
