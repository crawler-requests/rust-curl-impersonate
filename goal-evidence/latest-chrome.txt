3. transport change: captured extension 51764 (trust anchors) is now sent
   Chrome 156+ carries draft-ietf-tls-trust-anchors as extension 51764
   (0xca34). The capture payload is a u16 list length followed by
   length-prefixed trust-anchor identifiers. BoringSSL exposes
   SSL_set1_requested_trust_anchors() and takes exactly that identifier list.
   - tools/gen_fingerprints.py: 51764 is a supported extension; the identifier
     bytes are stored as hex in the record field `tls.trust_anchors`.
   - src/fingerprint/mod.rs: TlsFingerprint::trust_anchors -> wreq
     TlsOptions::trust_anchors; src/policy.rs validates the list framing.
   Effect: chromium157's extension set now matches its capture exactly, and
   Chrome 158/159/160 only miss 4832 (server padding request, whose
   SSL_set_server_padding_request API is not in the bundled BoringSSL).

   - the fresh chrome160 record is a TLS+HTTP/2 capture (tls.peet.ws did not
     complete an H3 handshake from this network), so `http3("chrome160")` is
     not defined; H3 for Chrome is available through the chrome152 preset.
   - during this session quic.nginx.org began rejecting requests from this
     network with H3_REQUEST_REJECTED (260), including presets that succeeded
     minutes earlier (external/rate-limit behaviour, no QUIC code changed).
   - re-checked on 2026-11-17: chrome152/firefox147/safari270 now all complete
     H3 live (`:status: 200`, `x-quic: h3`, 2523-byte body) once the
     active_connection_id_limit bug below was fixed; remaining 260 replies are
     the nginx edge's application-level policy for this source IP. See
     goal-evidence/h3-active-connection-id-limit.txt.
   - 2026-11-17 fix: quinn-proto sent active_connection_id_limit 5 while
     Firefox (8) and Safari (64) presets advertise their own value; the peer
     filled that window and quinn aborted with CONNECTION_ID_LIMIT_ERROR (0x9).
     quinn-proto now sizes its CID queue from the same value it advertises,
     src/quic/params.rs records parameter 0x0e and parses
     `chosen@alternative,...`, and endpoint transport_config copies the preset
     value in. All 10 H3 presets handshake without 0x9.

8. residual deviations (all in the record's `deviations`)
   - extension 4832 (server padding request): bundled BoringSSL lacks
     SSL_set_server_padding_request; Chrome 160 sends payload 0000.
   - mldsa44/mldsa65/mldsa87 signature algorithms and signature_algorithms
     GREASE: BoringSSL cannot send them.
   - pre_shared_key: only sent when a cached ticket is supplied; a fresh
